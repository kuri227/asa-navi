# モバイルハーネス監査 — 2026-11-15

対象: Expo SDK 58。`src/app`、画面と共通部品、theme、hooks、Planning Engine、UseCase、SQLite、通知、テスト、ビルド設定とCIを横断走査した。指摘箇所をコードで追い、修正対象は回帰テストを追加した。これは全端末・全状態の動作保証ではない。

## 実装した修正

| 基準            | 発見した問題                                                                                                                                           | 修正と根拠                                                                                                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M01             | 通常画面と別のネイティブモーダルが、ルートと同じSafe Area Contextに依存していた。                                                                      | 並べ替えモーダル内にネイティブ専用の測定境界を追加。iOS・Android・Webの構成差を単体テストで検証。実寸は未確認。                                                                                                                     |
| M06 / M08 / M10 | 通知の取消前にセッションをcancelledにすると、取消が失敗した後、再読込でそのセッションを探せなかった。                                                  | 取消・予約記録の更新が成功してからセッションを確定。OS側の取消失敗を注入して再試行を確認。                                                                                                                                          |
| M06 / M08 / M10 | ホームの再フォーカスとアプリ復帰が重なると、複数の読み込みが同じ予約状態を同時に読み書きできた。                                                       | ホームの読み込みと通知同期を直列化し、失敗が次の要求を止めないようにした。同時進行しないことを遅延テストで検証。                                                                                                                    |
| M09             | タスクテンプレートの全削除が過去の実行履歴の参照を壊し得た。Expoのネイティブ専用トランザクションでは、元接続の外部キー有効化が別接続へ伝わらなかった。 | 旧テンプレートを無効化して残し、新規タスクを有効化。別接続に外部キー制約を設定してからトランザクションを開始する。既存migrationは未変更。SQLite CLIで実行履歴の参照・外部キー整合性を検証。既に端末にある参照欠損は自動修復しない。 |
| M09             | 朝タスク完了・省略と続く再計画は別々に書き込まれ、再計画だけ失敗すると途中の進捗が残った。                                                             | 朝セッション操作の全書き込みを1トランザクションに統合。再計画が失敗しても途中の完了・入れ替えが確定しないことを接続のテストダブルで検証。                                                                                           |
| M10             | 入力された予定名が、新規通知の本文からロック画面に出る可能性があった。                                                                                 | 新規通知を汎用文言に変更。既にOSへ登録され再利用される通知は、既存予約の安定性を優先し、変更・再予約されるまで本文を変更しない。                                                                                                    |
